## 1. 目标与完成标准

本路线图把每日自动化固定为 17 个有序阶段，并把当前 PC 实现、今日实机结果、MFABD2 业务流程参考和仍缺少的 PC 证据放在同一份可执行清单中。

完成标准不是“代码里出现了入口”，而是每个启用阶段都满足以下条件：

1. 有 PC 客户端正例、相邻页面负例、无奖励/资源不足或危险确认页截图；
2. 离线截图回放能够区分入口、过渡、成功、可安全跳过和必须停止；
3. 单步实机 Demo 从已知入口闭环到稳定退出点，并保留点击标注、事件日志和最终截图；
4. 未识别页面、识别冲突、点击无效和资源/付费风险均 fail-closed，不回落到上游 ADB/PlayCover 坐标；
5. 正式编排按固定顺序执行，失败停在当前阶段；同一游戏日续跑不重复已完成阶段；
6. 只有全部启用阶段完成或被明确安全跳过后，才允许进入“结束游戏”策略。

非目标：本路线图不把上游脚本直接移植成 PC 坐标，不把尚未做 Demo 的模块写成“已完成”，也不以红点本身替代页面和次数识别。

## 2. 当前实现事实

### 2.1 当前主流程

`tools/daily_automation.py::run_daily` 当前真实顺序为：

```text
网络检查
→ 启动/进入游戏
→ 返回主页
→ 快速狩猎（狩猎场 → 圣石洞穴）
→ 人物与装备免费抽卡
→ 每日竞技场
→ 经营管理/餐馆常客奖励
→ 每日/每周任务奖励
→ 活动奖励
→ 通行证奖励
→ 邮件奖励
```

当前实现的关键边界：

- 每日刷新点为本地时间 08:00；互斥锁防止并发运行。
- 主流程在快速狩猎入口传入 `require_notification=False`，即使主页没有红点也会进入页面读取真实可用次数。这是 2026-09-18 实机证据确认后的有意行为。
- 任一必需阶段失败会停止并保留现场、日志和截图；不会继续盲点后续步骤。
- `state/daily_automation.json` 已升级为逐阶段状态；`completed/skipped` 同日不重放，`running/failed` 会从该阶段继续，`--force-phase` 可只重跑一个现有阶段。
- `tools/daily_plan.py` 已接入只读计划和主编排，固定 17 阶段与 `fast/detailed` 预设；默认计划任务只执行已有 PC 能力，显式完整预设有缺失阶段时在启动游戏前失败。
- `quick_hunt` 与 `daily_claims` 均明确标为 `partial`；兼容编排可以运行已验证子流程，但不会把目标业务完整度标成已实现。
- 当前成功后只退出 Python 流程，不关闭 PC 游戏进程。

## 4. 方向证据

### 4.1 MFABD2 能提供什么

本地 `.target/MFABD2` 的 `origin/codex/pc-client-mvp` 分支包含任务目录、base pipeline、少量 PC 覆盖和《PC 流程复刻指南》。其中任务入口可作为业务语义和目标顺序的参考：`StartGame_Start`、`QuickHunt_Start`、`Equip_HomePage`、`Gacha_HomePage`、`Collect_StartGame_HomePage_OnlyOnce`、`PVP_TaskStart`、`Event_HomePage`、`Weekly_Start`、`Daily_HomePage`、`RewardsDaily_Start`、`Activities_Start`、`Pass_HomePage`、`Mail_HomePage`、`Redemption_HomePage`、`Arbitrage_Start`、`Collect_StartGame_HomePage`、`Close_HomePage`。

上游证据的使用边界：

- 上游大多数上述任务在目录中仅声明 `Adb` 控制器；“PC 客户端”只覆盖启动、快速狩猎 MVP、单章采集 MVP 和邮件等少数入口。
- 上游 base pipeline 的坐标、滑动、`StopApp(package=com.neowizgames.game.browndust2)` 和页面结构面向 ADB/PlayCover/移动端语义，**不能直接复制到本项目 Windows PC 客户端**。
- 上游 PC 指南本身也要求每条新链路先收集真实 PC 正例、负例、失败例，做最短闭环 Demo；未知页面必须停止，不能回落到 Android 坐标。
- 本地 `.target` 当前 `main` 是精简后的 `0e9fa0a`，PC 复刻材料位于 `origin/codex/pc-client-mvp`（`8d3d589`）。自动化记忆记录曾只读比较 `sunyink/MFABD2 main a53bf199`，但该对象当前不在本地 `.target` 引用中；本轮又禁止联网，因此不能在本次核对中重新验证该远端快照。

### 4.2 已选方向

- 固定 17 阶段顺序不再随预设变化。
- 已定义并接入“尽快完成（`fast`）”和“费时细致（`detailed`）”两个目标预设：两者顺序相同，仅 `fast` 默认关闭肉鸽塔；当前缺失阶段会在完整预设预检时明确阻塞。

- 每阶段必须有稳定起点和稳定退出点，正式编排负责阶段前后回主页/目标页面复位。
- 快速狩猎内部固定为：

## 6. 可执行实施路线

### M0：冻结契约与安全选择

- 固化上表 17 阶段 ID、顺序、启用预设和“完成/跳过/不可用/失败”的含义。
- 用户确认装备白名单、套利白名单、结束游戏策略。
- 给每阶段定义稳定入口、成功退出、可安全跳过和必须失败四类条件。

退出条件：第 7 节的三组待决项均有明确答案；17 阶段清单不再因选项改变相对顺序。

### M1：逐阶段恢复与只读计划底座（已完成）

- 已接入 `daily_plan.py` 与 `daily_state.py`。
- 将阶段状态按游戏日原子持久化；`running/failed` 可续跑，`completed/skipped` 不重放。
- 增加只读计划输出，展示本次会运行/跳过/阻塞的阶段，不点击游戏。

## 7. 必须先决定的安全白名单

### 7.1 装备白名单（未确认，阶段 3 保持关闭）

建议的最小默认边界：

1. 制作仅允许一个精确配方：上游所述 **N 稀有短剑**；数量默认 1。
2. 强化仅允许“本次运行刚制作且已再次核对名称/稀有度”的物品，费用和目标等级必须在确认页重新读取。
3. 分解仅允许同一件本次新制作物品；锁定、装备中、有自定义标志或身份不一致时停止。
4. 精炼默认关闭。不能把“任意 SR/UR”直接当安全白名单；需要用户给出允许的装备名称/唯一标识、稀有度、部位、当前精炼上限、单次材料/金币上限。
5. 不允许自动解锁、不允许操作已有背包装备、不允许在 OCR 只确认稀有度但未确认身份时继续。

待用户确认：N 短剑的准确游戏内名称、每次制作数量、强化目标等级、是否允许分解、精炼装备清单及单日成本上限。

### 7.2 套利白名单（未确认，阶段 15 保持只读）

每个允许商品必须有：精确名称或稳定图标、操作类型（买/卖/制作）、单次及单日数量上限、最高买价、最低卖价、单日金币风险上限；料理还需配方和材料保留量下限。未列出的商品一律不操作。

首个白名单建议只选 1 个低价值、价格易读、数量可精确确认的商品，并分两步验收：先只读识价，再经确认做 1 件交易。上游的“收藏一键购买”“最高价抛售”不能直接作为 PC 安全默认值。

待用户提供：允许的商品/料理、买卖方向、价格阈值、数量上限、材料保留量和单日最大损失。

### 7.3 成功后结束游戏策略（未确认，阶段 17 不执行）

候选策略：

- **A（建议）**：仅当所有启用阶段为 `completed/skipped` 且无 `failed/unavailable` 时，向已验证的 BrownDust II PC 顶层窗口发送正常关闭；等待退出，超时则保留现场，不强杀启动器。
- **B**：自动化结束后回主页并保持游戏运行。
- **C**：正常关闭失败后精确终止已验证 PID；风险更高，需要单独确认，且不能按模糊名称批量杀进程。

还需决定：禁用阶段是否计为可成功结束、`unavailable` 是否阻止关闭、是否保留启动器、手动单阶段运行后是否永不自动关闭。
