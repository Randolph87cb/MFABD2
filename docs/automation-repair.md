# 无人值守修复规范

目标是提高真实日常完成率。先解释“截图正常，为何程序拒绝或没有继续”，再修改对应判据。

## 读取与定位

1. 先读最新 `summary.json` 的 `failures`、状态和各失败步骤的 `failure.txt/events.jsonl`，对照输入前后截图。汇总全部失败，优先处理共同原因；区分点击没生效、OCR 错误、条件过严、流程遗漏和环境故障。
2. 监督器 `events.jsonl` 用于执行/修复结果；`supervisor.log` 含 CLI 工具输出及历史日志的嵌套副本，只按来源、时间、行范围读取，不要整段输出或反复把日志自身读回上下文。
3. 先读相关实现与测试，再参考只读 `.external/MFABD2-reference` 对应业务与识别节点。借鉴稳定前缀、ROI、条件组合和恢复语义，不复制 Android 坐标或架构。

## 通用修复

- 标题按已确认区域内的完整关键词包含关系识别，结合相邻固定控件，不因附加问号、帮助文字或装饰而要求枚举分支。
- 全图 OCR 合并跨区域文字时，裁剪目标区域重新识别。数值仍需完整格式、置信度及必要的连续帧校验，不从长句截数字、不猜余额。
- 赛季、皮肤和背景变化不应改变共同布局判据；优先共同菜单、位置与标题前缀。页面身份不等于免费战斗或消费许可，行为许可须独立验证。
- 点击无效：新截图确认仍在同一来源页时才允许有限重试；已变为未知页不得重复输入。区分页面没打开和目标页识别失败。
- 阶段失败保留原始错误，确认回到主页后继续后续独立阶段；无法恢复、登录/维护阻塞时停止。已完成消耗阶段不重放；任务、活动、通行证、邮件每轮重查。
- 最小改动指只改相关根因，不是只允许为当前截图加特例。检查同类判据及下一个状态转换，避免一轮只修第一个表象。确需特例时说明稳定业务差异和不能共用的证据。

## 验证与交付

- 使用真实失败图、已有跨日正例和相邻页面/遮挡负例验证；必要时加少量体现行为差异的测试。识别变化和状态机续跑分别验证，不只复制本次截图的文字作为断言。
- 更换 OCR 模型前，用相同截图比较错误率、置信度、耗时和依赖成本；区域隔离能解决时不默认换模型。
- 禁止自行启动游戏、执行日常、强制阶段或修改/重置每日状态。真实续跑由监督器完成；不得用离线通过宣称游戏验收通过。
- 保持网络无限等待和精确进程收尾；禁止修改参考仓库或提交 logs、state、.external。
- 必要验证后提交推送 main。报告根因、通用机制、测试、提交推送、下一轮仍需确认的实跑行为。
