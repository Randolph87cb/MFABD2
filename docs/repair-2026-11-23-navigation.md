# 2026-11-23 无人值守第 1 轮修复

来源：`logs/daily/2026-11-23/083006/summary.json` 及各失败步骤的事件、输入前后截图。只调用本地 `status`，返回无游戏窗口；未启动游戏、未发送游戏输入、未修改每日状态。

## 根因和修复

- 赛季：入口实际存在、三项余额完整；全图 OCR 漏掉活动面板的倒计时。仅当该 ROI 没有文字框时裁剪重读，仍要求唯一完整 `D-数字/DAY`、置信度及解锁文字。不以赛季名称或美术放行，不改变战斗资格和费用许可。
- 小屋第二次入口、广场卡带入口：等待期间截图仍是主页，没有到达目标页。共用导航等待与重试：最多两次输入，超时后重新截图；目标已到达直接结束，只有确认原可操作主页才允许第二次输入，未知页不重试。点赞、祈求等业务动作不走此重试。
- 经营管理：第一次验证把暗化主页当成过渡，后续等待实际回到了主页，却直接失败。保留过渡观察，补上新帧确认主页后的单次入口重试；过渡不代表最终成功，必须识别管理弹窗。
- 餐馆：NPC 对话与标题区域重叠，全图及原宽裁剪读出标题碎片，餐馆身份失败后被通用抽卡动画亮度判据接走。裁剪标题文字基线、排除上方对话并统一放大 OCR；仍要求完整餐馆标题、结算和相邻固定控件。遮挡标题的负例不能认成餐馆。

共同问题是把全图 OCR 或瞬态视觉分类当成最终判据，没有充分隔离固定文字区域，也缺少来源与目标双向确认。参考只读仓库 `assets/resource/base/pipeline/Daily.json` 的经营管理、餐馆和广场节点，借鉴 ROI、页面确认与加载回跳语义；未复制 Android 坐标或宽松标题正则，未修改参考仓库。
